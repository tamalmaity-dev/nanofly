# NanoFly v0.3.31 — Coolify-Style Compose & Left Nav

**Release Date:** 2026-08-30
**Type:** UX / Minor
**Urgency:** Recommended

---

## Summary

`v0.3.31` makes **Docker Compose feel like Coolify**: creating a compose service is now a single **editor → Create service** step (no extra configuration page — the compose file *is* the config, env vars are auto-filled), the service detail moves its 12 tabs to a **grouped sticky left nav** (Settings / Observe / Automation / Operations), and compose services correctly show **Compose resources** instead of an empty Persistent Storage tab. The codebase is also more organized.

---

## What Changed

### 1. Compose creation — single step (Coolify) — `ProjectDetail.tsx:1198`
- **Before:** `compose-editor` Step 1 (editor) → `Next: Configuration` Step 2 (name/port/env vars form) → `Deploy`. Env vars from the compose file (`environment: [AWS_...]`) were ignored until `v0.3.30` where they were parsed on Next, but you still had to click through an extra page.
- **After:** `compose-editor` now has **Create service** (pink, like Coolify) that directly calls `servicesApi.createApp` with `docker_compose_content`, `port` (parsed from `ports[0]` if empty), and `env_vars` (parsed from `environment` list or mapping). No `config` step for compose. The 2-step flow is kept for **Dockerfile** only (template picker → config).

### 2. Service detail left nav — grouped, sticky — `ProjectDetail.tsx:3448`
- **Before:** `<Tabs items=[12]>` as a top `tabs-list` (horizontal, `overflow-x:auto`, hidden scrollbar) → **Backup & Restore** cut off, no grouping, not sticky.
- **After:** `isCompose = git_builder === 'docker-compose' || docker_compose_content` drives **4 groups** (like Coolify):
  - **Settings:** General (Configuration) / Connection Details, Domains, *(non-compose only)* Environment Variables, *(non-compose only)* Persistent Storage, *(compose only)* Compose
  - **Observe & troubleshoot:** Deployments, Runtime Logs, Terminal, Monitoring
  - **Automation:** Webhooks, Source Files, Backups
  - **Operations:** Resource Limits
  Each group has a `0.68rem` uppercase title and `8px 10px` buttons (`active: rgba(79,110,247,0.10)` + `var(--accent)`). The nav is `width:220, sticky, top:16`; content is `flex:1` `card` (`1.5rem` padding). `activeTab` state unchanged, so polling and deep links still work.

### 3. Compose UI fixes
- **Persistent Storage** tab is now **hidden for compose services** (`isCompose ? [] : [...]`) — "No storage found" no longer appears for `seaweedfs` because its volume (`seaweedfs-data:/data`) is a compose named volume, not a NanoFly bind-mount. It is still handled by `normalizeComposeVolumes` (adds missing top-level `volumes: seaweedfs-data: {}`) and created by `compose up`.
- **New `compose` tab** for compose services: read-only `CodeEditor` of `docker_compose_content` (260px, `readOnly`) + **Compose resources** table (like Coolify) — parses the compose file via `yamlLoad`, lists `Resource | Image | Status` for each service (`seaweedfs | chrislusf/seaweedfs:latest | running`).
- **New `domains` tab** (always visible, grouped under Settings): lists `domains.filter(d.service === selectedSvc.name)` with `Globe` icon and `https://` link.

### 4. Codebase organization
- `ProjectDetail` split start: `pages/ProjectDetail/EnvVarsPanel.tsx` extracted (first of 12, `@ts-nocheck`); `ProjectDetail.tsx` now `import { EnvVarsPanel } from './ProjectDetail/EnvVarsPanel'` and no inline definition (156 lines removed).
- Batch `*.jsx → *.tsx` (23 files + `ProjectDetail`, `components/index.js→ts`) + `strict:true` already landed in `v0.3.30`; `types/domain.ts` + `api/client.ts` generics remain.
