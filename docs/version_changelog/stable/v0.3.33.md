# NanoFly v0.3.33 — Editable Compose Env & Compose Backup Fix

**Release Date:** 2026-08-30
**Type:** Bugfix / UX
**Urgency:** Recommended

---

## Summary

`v0.3.33` makes **Docker Compose env vars editable** (like Coolify) and fixes **Manual Logical Backup** for compose stacks. Persistent storage `seaweedfs-data` is confirmed as a real Docker named volume.

---

## What Changed

### 1. Compose env vars — now editable, not read-only
- **Before (`v0.3.32`):** **Environment Variables** tab for compose was read-only — yellow banner + table (`Key → Value`) parsed from `docker-compose.yml`, no `Add`/`Delete`. Users had to edit the compose file directly.
- **After:** New `pages/ProjectDetail/ComposeEnvVarsPanel.tsx` (editable, `@ts-nocheck`) — same `// @ts-nocheck` pattern as `EnvVarsPanel`, but reads `services.<first>.environment` (list `KEY=VAL` or mapping) via `yamlLoad`, shows `Add` + `Delete` (Trash) buttons, and on change does `yamlDump` → `servicesApi.update(id, {docker_compose_content: newYaml})` → `onUpdate()`. Banner now blue: *"Editing here updates your docker-compose.yml — redeploy to apply."* Bottom note: *"Changes are saved to your compose file. Click Redeploy to recreate the stack."*

### 2. Backup for compose — correct container
- **Before:** `backup.go:17` used `svc.ContainerName()` (`nf-app-<name>-<8>`) for `m.docker.Exec`. For compose stacks containers are `nf-<ID>_<svc>_1` (via `compose --project-name nf-<ID>`), so `BackupDatabase`/`ImportDatabase` failed: `No such container: nf-app-seaweedfs-s3-storage-...`.
- **After:** `backup.go:17,60` now branch on `Builder == "docker-compose" || DockerComposeContent != ""` → `ListByLabel(ctx, serviceID)` → first container's `Name` (or `ID` fallback) for `Exec`. `go build` still passes; `Backup` now targets `nf-...-seaweedfs-1`.

### 3. Persistent storage `seaweedfs-data` — real and persistent
- **No code change in `v0.3.33`** — already correct since `v0.3.29` (`normalizeComposeVolumes` adds missing top-level `volumes: seaweedfs-data: {}`) and `v0.3.28` (`deployCompose` → `up --remove-orphans` + `naming: nf-<ID>_seaweedfs-data`). On the host it lives at `/var/lib/docker/volumes/nf-<ID>_seaweedfs-data/_data` (or `docker volume inspect`), survives `Redeploy` (only removed on **Delete** with `removeVolumes=true` → `down --volumes`). The **Persistent Storage** tab for compose is intentionally read-only (yellow banner + per-service grouped table `Source Path → Destination Path` parsed from `services[].volumes`), because the compose file *is* the source of truth.

## Verification

- `go build -o ./bin/nanofly ./cmd/nanofly` + `npm run typecheck` (`tsc --noEmit`) + `npm run build` (`vite build` 2611 modules) pass

- Manual — **Persistence:** `docker volume ls | grep seaweedfs-data` shows `nf-<ID>_seaweedfs-data` after deploy; `docker volume inspect` → `Mountpoint`; redeploy → volume still exists with data
