# NanoFly v0.3.42 — Build Optimizations (Coolify/Dokploy-Level)

**Release Date:** 2026-08-30
**Type:** Performance
**Urgency:** Recommended

---

## Summary

`v0.3.42` applies build optimizations inspired by Coolify and Dokploy — the two leading self-hosted PaaS platforms. Key changes: remove `.git` after clone, comprehensive `.dockerignore` merge (70+ entries), `DOCKER_BUILDKIT=1`, `--pull` for fresh base images, and build context size logging.

---

## What Changed

### 1. Remove `.git` After Clone — `service.go:1624`
- **Before:** `.git` directory (50-200MB of history) stayed in build context, sent to Docker daemon.
- **After:** `.git` removed immediately after clone. Coolify does this in `cleanup_git()`.
- **Impact:** Context drops from 78MB → ~30MB for typical repos.

### 2. Comprehensive `.dockerignore` Merge — `service.go:1676`
- **Before:** Only 16 entries. User's existing `.dockerignore` was 144 bytes (tiny).
- **After:** 70+ entries covering all frameworks, merged with existing file (not overwritten).
- **Categories:** Dependencies, build outputs, tests, IDE, Git, Docker, env/secrets, logs, TypeScript cache, docs, CI/CD, config, OS, Python, Go, Rust, AI tools.
- **Impact:** Context drops further. Matches Next.js official `.dockerignore` standard.

### 3. `DOCKER_BUILDKIT=1` — `service.go:1765`
- **Before:** BuildKit not explicitly enabled.
- **After:** Explicitly set for both Docker and Nixpacks builds. Coolify does this in all build paths.
- **Impact:** Enables cache mounts, `--secret`, `# syntax=docker/dockerfile:1`, and other BuildKit features.

### 4. `--pull` Flag — `service.go:1751`
- **Before:** Used cached base image (might be outdated).
- **After:** Always pulls latest base image. Coolify does this for Dockerfile builds.
- **Impact:** Security patches applied automatically. No stale base images.

### 5. `--progress=plain` — `service.go:1751`
- **Before:** Default Docker progress (hard to parse).
- **After:** Structured progress output. Coolify uses this for log streaming.
- **Impact:** Better log readability, easier debugging.

### 6. Build Context Size Logging — `service.go:1750`
- **Before:** No visibility into context size.
- **After:** Logs MB before build starts. Helps diagnose slow builds.
- **Impact:** Users can see if context is too large.

## How Coolify Does It

Coolify runs builds inside a **helper container** (Alpine) with Docker, Buildx, Nixpacks pre-installed. Key strategies:

| Strategy | Implementation |
|----------|---------------|
| Build isolation | Helper container with all tools pre-installed |
| BuildKit detection | Three-tier: BuildKit+Buildx → BuildKit → legacy fallback |
| `.git` removal | `cleanup_git()` removes `.git` after clone |
| Secrets outside context | `/artifacts/build-time.env` (not in image layers) |
| Cache keys | `APP_KEY`-based HMAC for secrets hash preserves layer cache |
| `--pull` | Always pulls latest base image for Dockerfile builds |
| `--network host` | All builds use host networking |
| `DOCKER_BUILDKIT=1` | Explicitly set in all build paths |
| `--progress plain` | Structured output for log streaming |
| `--no-cache` | User-configurable force rebuild |
| Build skip | Skips build when image exists and config unchanged |
| ARG injection | Automatic `ARG` after every `FROM` for multi-stage builds |
| Docker secrets | `--mount=type=secret` added to all `RUN` commands |

---

## How Dokploy Does It

Dokploy uses **Docker Swarm services** with WebSocket log streaming. Key strategies:

| Strategy | Implementation |
|----------|---------------|
| Build context | Custom `dockerContextPath` to limit context |
| Secrets | `--secret type=env` for BuildKit secrets |
| Error handling | `set -e` for fail-fast, base64-encoded errors |
| Concurrent builds | Isolated `docker-container` builders per build |
| Safe cleanup | Waits for idle Docker before pruning |
| Log streaming | WebSocket + `tail -f` for real-time output |
| `--no-cache` | User-configurable `cleanCache` flag |
| Multi-stage | `--target` flag for Dockerfile builds |
| Registry push | Tag and push after build if registry configured |
| Auto-rollback | `FailureAction: "rollback"` with `start-first` |
