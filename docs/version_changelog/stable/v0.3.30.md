# NanoFly v0.3.30 — Compose Env Auto-Fill & Service Left Nav

**Release Date:** 2026-08-30
**Type:** UX / Minor
**Urgency:** Recommended

---

## Summary

`v0.3.30` makes the Compose creation flow feel finished: env vars pasted in the compose editor are now parsed and pre-filled in **Configuration** (Step 2) before you deploy, and the service detail view moves its 12 tabs from a cramped top row to a **sticky left sidebar** like Coolify — always visible, no horizontal scroll.

---

## What Changed

### 1. Compose env auto-fill — `ProjectDetail.tsx:1198`
- **Before:** `Next: Configuration` only copied `ports[0]` → `port` and `image`. `environment:` in the compose file was ignored, so you had to re-type `AWS_ACCESS_KEY_ID`, `S3_BUCKET`, etc. in the Configuration step or the **Environment Variables** tab after creation.
- **After:** On `Next`, `yamlLoad(dockerComposeContent)` also reads `services.<first>.environment` — supports both ` - KEY=VAL` (list) and `KEY: VAL` (mapping) — joins with `\n` and sets `form.envText`. The Configuration step’s **Env Vars** textarea is now pre-filled; `normalizeComposeVolumes` still handles the named volume (`seaweedfs-data:/data`) via the compose file itself.

### 2. Service detail left nav — `ProjectDetail.tsx:3448`
- **Before:** `<Tabs items=[12]>` rendered as a top `tabs-list` (`overflow-x:auto`, hidden scrollbar) → **Backup & Restore** was cut off on narrow viewports, no affordance.
- **After:** `navItems` array (same 12 ids) rendered as a **210 px sticky left column** (`position:sticky; top:16`) of full-width buttons (`gap 10`, `9px 12px`, `border 1px`, `background rgba(79,110,247,0.10)` when active, `color var(--accent)`). Right side is the `card` content (`flex:1`). `activeTab` state is unchanged, so deep links and polling (`load` every 5 s when `activeTab` not in `configuration/resources/envvars`) still work. Icons preserved (`Package` for Deployments, `FileText` for Logs, etc.).
