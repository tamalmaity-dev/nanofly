# NanoFly v0.3.28 — Reliability, Watcher, Builder Wizards & TypeScript Foundation

**Release Date:** 2026-08-29
**Type:** Minor / Reliability + DX
**Urgency:** Recommended

---

## Summary

`v0.3.28` is a **reliability and developer-experience** release that hardens the Compose lifecycle, bounds deployment logs, reclaims disk automatically, adds file-watching auto-redeploy, unifies builder creation flows, and lays a strict TypeScript foundation. The one-line fix for *"Compose containers had no `nanofly.service` label, so status/logs/cleanup could not see a multi-container stack"* is now a full lifecycle fix (prepare → validate → apply → discover → teardown). No API breaks; upgrade is a drop-in `nanofly` binary replace.

## Reliability Fixes (detailed)

### 1. Compose label lifecycle — `compose.go:25,152` + `service.go:2325`
- `deployCompose` now does `backupComposeFile` → `normalizeComposeVolumes` → `ensureComposeServiceLabels` → `config --quiet` → `up --detach --build --remove-orphans` with `--project-name nf-<full-UUID>` and `--file <discovered>` (via `findComposeFile` trying 4 variants).
- `DockerStatus`/`GetContainerLogs` try `ListByLabel` first, then `docker ps -a --filter name=nf-<ID>` for compose stacks; `GetContainerLogs` aggregates logs from all containers in a stack (`── name ──` headers).
- `teardownContainers` tries `compose down --project-name nf-<ID> --file <path> --timeout 5 --remove-orphans` (plus `--volumes --rmi local` on Delete), then label scan, then `primaryContainerNames` fallback. Orphan stacks are now reachable even if the compose file was deleted.

### 2. Dead code & file safety — `service.go:2686`
- Deleted `ensureComposeVolumes` (string-split `docker volume create` parser, 0 call sites, superseded by `normalizeComposeVolumes` YAML-node logic) — 130 lines removed.
- `file://` compose mutation now has `.bak` guard; `Delete` cleans all 4 variants (`docker-compose.yml/.yaml`, `compose.yml/.yaml` + `.nanofly.bak`).

### 3. Tabs — `Tabs.tsx`, `index.css:1356`
- `RadixTabs.List` wrapped in `tabs-list-wrap` with `ResizeObserver` + scroll listeners, `canScrollLeft`/`canScrollRight` state, chevron buttons (`ChevronLeft`/`Right` from `lucide-react`), `scrollBy(160)` and `scrollIntoView({behavior:"smooth", inline:"center"})`.

## Deploy Pipeline Hardening — `service.go:836`

- **Log caps:** `logBuf` capped at 2 MB; on overflow keep 1.5 MB tail with `[… truncated …]` marker. Flush condition is `now.Sub(lastWrite) > 1s || logBuf.Len() >= 64k` (was only time-based). Prevents `deployments.log` OOM on huge builds.
- **Graceful shutdown:** `Manager.deployWg sync.WaitGroup` + `WaitForDeploys(ctx)`; `Deploy` does `Add(1)` before `go func()` and `Done()` in its defer. `Server.Stop` now does `StopAllWatchers()` → `WaitForDeploys(8s)` → `http.Shutdown`. `WatchEvents` and `backupScheduler`/`periodicCleanup` tickers are stopped via context.
- **Prune:** `periodicDockerPrune` ticker `7*24h` in `Server.New` (jitter ±1 h), `PruneSystem(false,true,false,false)` (dangling images only, never volumes), `NANOFLY_AUTO_PRUNE=0` to disable, `ReclaimedHuman` logged.

## File Watching — `watcher.go` (new, 170 lines)

- `fileWatcher` per `file://` service with `patterns = parseWatchPatterns(build_watch_paths)` (comma-split), `shouldIgnoreWatchPath` (`.git`, `node_modules`, `.venv`, `*.log`), `matchesWatch` via `doublestar.PathMatch` + `filepath.Match` fallback.
- `run()` ticker 2 s, `filepath.Walk` + `Rel` + `ModTime` map, `changed` detection, `pending` debounce 750 ms, coalesce to 1 `Deploy` per 2 s, `slog.Info` on trigger.
- `Manager.StartWatchers` scans `SELECT ... WHERE git_repo_url LIKE 'file://%' AND build_watch_paths != ''` on boot; `SyncWatcher` on `CreateApp`/`Update`, `stopWatcherLocked` on `Delete`; `NANOFLY_WATCH_REQUIRE_FLAG=1` gates on `build_use_server`.
- Dep `doublestar/v4 v4.10.0`.

## Upgrade Notes

1. Replace `nanofly` binary (`bin/nanofly` or `bin/nanofly-linux-*`) and restart (`systemctl restart nanofly` or `docker restart`).
2. No DB migration — `build_watch_paths`/`build_use_server` columns already exist.
3. Existing `file://` services with `build_watch_paths` will auto-start watchers on next boot; set `NANOFLY_WATCH_REQUIRE_FLAG=1` to require `build_use_server` flag.
4. Weekly prune is opt-out via `NANOFLY_AUTO_PRUNE=0` (env). Volumes are never auto-pruned.
5. Frontend is now `strict:true` with `allowJs:true`; `// @ts-nocheck` files will be typed incrementally — no runtime change.
