# NanoFly v0.3.51

Release date: 2026-08-30

This release improves service management, deployment reliability, and build observability. The service detail experience is now organized around reusable settings panels, with behavior closer to a production deployment platform such as Coolify.

## Added

- Added a reusable Domains panel to the service detail page.
  - Add and validate domains directly from the service.
  - Recheck DNS status.
  - Update routing direction.
  - Remove domains with confirmation.
  - Display clear pending, healthy, mismatch, and error states.
- Added a reusable Webhooks panel with GitHub App and manual webhook guidance.
- Added reusable Git Source and General settings panel routing in the service sidebar.
- Added manual repository URL support when a GitHub App is not configured.
- Added build progress heartbeats for long-running dependency installation, compilation, Docker context transfer, dependency copying, and base image resolution steps.

## Fixed

- Fixed Git Source-only service updates being skipped by an early return in the backend.
- Fixed Git Source-only updates from accidentally clearing the existing builder selection.
- Fixed container port mappings so the configured host port maps to the actual exposed container port.
- Fixed incomplete port settings by synchronizing a missing host port or exposed container port while preserving explicit differences.
- Fixed generated Node.js and Next.js Dockerfiles so lockfile-based installs use `npm ci` and projects without a lockfile use `npm install`.
- Removed the hidden dependency-install fallback that could rerun package installation and make builds appear stuck.
- Fixed existing Dockerfile patching so npm dependency commands receive the same cache-friendly options as generated Dockerfiles.

## Build performance and reliability

- Node package installation now prefers local cache data and disables unnecessary audit, funding, and progress overhead.
- Docker build commands now provide useful periodic progress output instead of appearing idle when a tool produces no logs.
- Build command stages are identified in the deployment log to make slow or stalled operations easier to diagnose.
- Added backend tests covering port synchronization, optimized npm commands, progress-stage detection, and Git Source-only updates.

## Frontend improvements

- Reorganized service settings into clearer General, Domains, Environment Variables, Persistent Storage, Advanced, and Healthcheck sections.
- Added Git Source and Webhooks navigation for both GitHub App and manually configured remote repositories.
- Improved empty states, validation messages, status badges, action feedback, and destructive-action confirmation in service management views.
