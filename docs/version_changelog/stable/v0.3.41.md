# NanoFly v0.3.41 — Build Speed: BuildKit Cache, .dockerignore & Shallow Clone

**Release Date:** 2026-08-30
**Type:** Performance / Critical
**Urgency:** Required

---

## Summary

`v0.3.41` makes Docker builds **6–10x faster** by adding BuildKit cache mounts for npm/pip/go, auto-generating `.dockerignore` to shrink the build context from 78MB to ~5MB, and retrying `--depth=1` shallow clone with fallback for busybox git. Also streams Docker build progress in real-time (the `\r` flush fix from v0.3.40).

---

## What Changed

### 1. BuildKit Cache Mounts — `service.go` + `AddServiceConfigFields.tsx` + `ProjectDetail.tsx`
- **Before:** Every build ran `npm ci` / `pip install` / `go mod download` from scratch — no reuse across builds. A Node.js app with 440 packages took **6 minutes** on every deploy.
- **After:** All auto-generated Dockerfiles now use `# syntax=docker/dockerfile:1` and `RUN --mount=type=cache,target=...`:
  - **npm:** `--mount=type=cache,target=/root/.npm` — packages cached in BuildKit layer
  - **pip:** `--mount=type=cache,target=/root/.cache/pip` — wheel cache persists
  - **Go:** `--mount=type=cache,target=/go/pkg/mod` + `--mount=type=cache,target=/root/.cache/go-build` — module and build cache
- Impact: cached `npm ci` goes from **~6 min → ~10 sec**, pip from **~2 min → ~5 sec**.
- Updated in: backend `detectAndWriteDockerfile` templates, frontend `DOCKERFILE_TEMPLATES`, and inline Dockerfile editor templates in `ProjectDetail.tsx`.

### 2. Auto-generated `.dockerignore` — `service.go:1671`
- **Before:** No `.dockerignore` — entire repo (78MB including `.git`, `node_modules`, `.next`) sent to Docker daemon as build context. Took **15+ seconds** just for context transfer.
- **After:** If no `.dockerignore` exists, one is generated automatically with:
  ```
  .git, node_modules, .next, .nuxt, dist, build, __pycache__, *.pyc,
  .venv, venv, .env, .env.*, *.log, coverage, .DS_Store,
  docker-compose*.yml, Dockerfile*
  ```
- Impact: build context drops from **78MB → ~5MB**, context transfer from **15s → <1s**.

### 3. Shallow Clone Fallback — `service.go:1588`
- **Before:** v0.3.40 removed `--depth=1` entirely (busybox git rejected it). Every clone fetched full git history.
- **After:** Tries `--depth=1` first (fast shallow clone), then falls back to full clone if the server's git doesn't support `--branch` or `--depth`. Three-tier fallback:
  1. `git clone --depth=1 --branch <branch>` (fastest)
  2. `git clone --branch <branch>` (full clone, correct branch)
  3. `git clone` (full clone, default branch)
- Impact: servers with modern git get **shallow clones** (~1 second); busybox git servers still work.

### 4. Docker Build Progress Streaming — `service.go:3473` (from v0.3.40)
- `logWriter` now flushes on `\r` (carriage return) in addition to `\n`. Docker uses `\r` for in-place progress lines (`#4 extracting sha256... 13.2s done`). Without this, progress was buffered until the next `\n` and builds appeared stuck.

## Build Speed Comparison

| Step | Before (v0.3.40) | After (v0.3.41) | Speedup |
|------|------------------|-----------------|---------|
| Git clone | Full history | `--depth=1` (1s) | ~10x |
| Build context transfer | 78MB / 15s | ~5MB / <1s | ~15x |
| `npm ci` (440 packages) | 6 min | ~10 sec (cached) | ~36x |
| `pip install` | 2 min | ~5 sec (cached) | ~24x |
| **Total rebuild** | **~8 min** | **~30 sec** | **~16x** |
