# NanoFly v0.3.39 — Migration Fix, Wizard Fixes & Branch Fallback

**Release Date:** 2026-08-30
**Type:** Bugfix / Critical
**Urgency:** Required

---

## Summary

`v0.3.39` fixes a **critical SQLite migration bug** that silently dropped all `ALTER TABLE` migrations after the first "column already exists" error — causing missing columns (`healthcheck_enabled`, `healthcheck_path`, `healthcheck_port`), broken project listing, and deploy failures. Also includes the GitHub App wizard fixes from v0.3.37–v0.3.38 (branch fallback, "Create Service" button).

---

## What Changed

### 1. SQLite Migration Cascade Fix — `internal/db/db.go` (Critical)
- **Before:** All `ALTER TABLE ADD COLUMN` statements ran inside a single `tx` transaction. When one failed (column already exists), SQLite marked the transaction as errored, silently aborting every subsequent ALTER — including `healthcheck_enabled`, `healthcheck_path`, `healthcheck_port`. This caused `SELECT s.healthcheck_enabled` to crash with `no such column`, and prevented new projects/services from loading.
- **After:** Schema `CREATE TABLE` commits in its own transaction first. Each `ALTER TABLE` then runs via `db.Exec()` independently (no wrapping transaction). A failure on one migration (column already exists) no longer affects any other. All 30+ migrations are now idempotent and independent.

### 2. GitHub App Wizard "Create Service" Button — `ProjectDetail.tsx`
- **Before:** After wizard called `onComplete`, `step` was set to `'config'` but `selectedResourceId` remained `'git-private-app'`, so the wizard component was always rendered — the config form with the submit button was never shown.
- **After:** Added `wizardDone` state. Wizard only renders when `selectedResourceId === 'git-private-app' && !wizardDone`. After wizard completes, `wizardDone=true` reveals `AddServiceConfigFields` with "Deploy Now" button. Back button resets `wizardDone`.

### 3. GitHub App Branch Fallback — `internal/api/services/service.go`
- **Before:** `git clone --depth=1 --branch main` was hardcoded. If the repo's default branch was `master` (or anything else), clone failed with `fatal: Remote branch main not found`.
- **After:** `git clone` now retries without `--branch` when the specified branch isn't found, falling back to the repo's default branch. Frontend wizard also passes `default_branch` from GitHub API instead of hardcoding `main`.

### 4. GitHub API Repo Metadata — `internal/api/github/service.go`
- `RepoInfo` struct now includes `default_branch`, `description`, and `private` fields from the GitHub API response.

### 5. Radix Select Empty-String Fix — `AddServiceConfigFields.tsx` + `GitSourcePanel.tsx`
- `SelectItem value=""` replaced with sentinel `__auto-link__` to prevent Radix UI `Uncaught Error` crash on page load.
