# NanoFly v0.3.29 — Compose External Network Auto-Create & Env/Volume Handling

**Release Date:** 2026-08-30
**Type:** Patch / Reliability
**Urgency:** High (fixes deploy failure for external networks)

---

## Summary

`v0.3.29` fixes a **deploy failure** when a Docker Compose file declares an `external: true` network (e.g. `coolify`) that does not yet exist on the host. The error `network coolify declared as external, but could not be found` is now auto-handled: NanoFly creates the network before `docker compose up`. Environment variables and named volumes in the compose file continue to be handled by `normalizeComposeVolumes` (already in `v0.3.28`) — no change needed there; this patch only adds the missing network step.

---

## Bug Fixed

**Deploy failed: `network coolify declared as external, but could not be found`**

- **Compose file:**
  ```yaml
  services:
    seaweedfs:
      image: chrislusf/seaweedfs:latest
      volumes: [ "seaweedfs-data:/data" ]
      networks: [ "coolify" ]
  networks:
    coolify:
      external: true
  ```
- **Before:** `deployCompose` did `config --quiet` → `up --detach --build --remove-orphans` without ensuring the external network exists → `docker compose up` exited 1.
- **Logs (before):**
  ```
  [INFO] Added missing Compose volume declarations: seaweedfs-data
  [INFO] Added NanoFly management labels to: seaweedfs
  Validating...
  Applying docker compose stack…
  network coolify declared as external, but could not be found
  [ERROR] Deploy failed: docker compose up: exit status 1
  ```
- **After:** `ensureExternalNetworks` runs before `normalizeComposeVolumes` → `docker network inspect <name>` → if missing, `docker network create <name>` (idempotent, `already exists` ignored) → `up` succeeds.

## Changes

| File | Change |
|------|--------|
| `internal/api/services/compose.go` | Add `ensureExternalNetworks(ctx, composePath, log)` — parses top-level `networks` via `yaml.Node` + `mappingValue`, detects `external: true` (scalar or mapping form), `docker network inspect` → `create` if missing, logs `[INFO] Creating external network: <name>` / `[WARN]` on failure. Called in `deployCompose` before `normalizeComposeVolumes`. |
| `VERSION` | `0.3.28` → `0.3.29` |

## Environment Variables & Persistence

No code change in `v0.3.29` — already correct since `v0.3.28`:

- **Env vars** in the compose file (`environment: [ AWS_ACCESS_KEY_ID, ... ]`) are passed through by `docker compose` itself. They do **not** need to be duplicated in NanoFly’s **Environment Variables** tab (which is for non-compose `docker run` services). If you need them in the UI, add them via the tab — they will be merged on `docker run` but are redundant for compose.
- **Named volumes** (`seaweedfs-data:/data`) are handled by `normalizeComposeVolumes` — missing top-level `volumes: seaweedfs-data: {}` is added before `config --quiet`, so the volume is created by `compose up` and survives `down` (only removed on Delete with `removeVolumes=true`). Check `Persistent Storage` tab for host bind-mounts, not compose named volumes.
