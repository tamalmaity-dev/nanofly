# NanoFly v0.3.34 — Compose Terminal & Editable Env

**Release Date:** 2026-08-30
**Type:** Bugfix / UX
**Urgency:** High (fixes compose terminal)

---

## Summary

`v0.3.34` fixes **Terminal for Docker Compose** (`No such container: nf-app-...`) and makes **compose Environment Variables editable** (not read-only) — changes are written back to `docker-compose.yml` via `yamlDump` and applied on next deploy. `Backup` for compose already fixed in `v0.3.33` (`ListByLabel`).

---

## What Changed

### 1. Terminal for compose — label fallback — `TerminalPanel.tsx:26`, `handler_unix.go:73`
- **Before:** Frontend hard-coded `nf-app-<name>-<8>` for all services; for compose the real container is `nf-<ID>_<svc>_1` (project `nf-<ID>`), so `docker exec -it nf-app-...` → `No such container` (8 repeats in the screenshot).
- **After:** Frontend: `isCompose = git_builder === 'docker-compose' || docker_compose_content` → `containerName = service.id` (UUID) for compose; backend: `handler_unix.go:73` detects service-ID-like `container` (UUID, `len==36` or `nf-` + `-`), runs `docker ps --filter label=nanofly.service=<ID> --format {{.ID}}` → first ID, then `docker exec -it <ID> /bin/sh`. Non-compose fallback also added: `docker inspect <name>` → if missing, scan `docker ps -a` for label and retry. `BackupDatabase`/`ImportDatabase` already fixed in `v0.3.33` with same `ListByLabel` pattern.

### 2. Compose env vars — editable — `ComposeEnvVarsPanel.tsx` (new), `ProjectDetail.tsx:3680`
- **Before (`v0.3.32`):** **Environment Variables** tab for compose was read-only — yellow banner + table (`Key → Value`) parsed from `services.<first>.environment`, no `Add`/`Delete`.
- **After:** New `pages/ProjectDetail/ComposeEnvVarsPanel.tsx` (`@ts-nocheck`, 170 lines) — parses `environment` (list `KEY=VAL` or mapping) via `yamlLoad`, shows `Add` (KEY + value) + `Delete` (Trash) per row, `saveToCompose` does `yamlLoad` → `parsed.services[svcName].environment = vars.map(v=>\`\${v.key}=\${v.value}\`)` → `yamlDump` → `servicesApi.update(id, {docker_compose_content: newYaml})` → `onUpdate()`. Blue banner: *"Editing here updates your docker-compose.yml — redeploy to apply."* `ProjectDetail.tsx:envvars` now branches `isCompose ? <ComposeEnvVarsPanel service={selectedSvc} /> : <EnvVarsPanel>`.

### 3. Persistence `seaweedfs-data`
- **No code change in `v0.3.34`** — already correct: named volume `nf-<ID>_seaweedfs-data` (`normalizeComposeVolumes` adds `volumes: seaweedfs-data: {}`), `up --remove-orphans` creates it at `/var/lib/docker/volumes/nf-<ID>_seaweedfs-data/_data`, survives `Redeploy` (only `Delete` with `down --volumes` removes). **Persistent Storage** tab for compose stays read-only (yellow banner + per-service `Source → Destination` table from `services[].volumes`), because the compose file is the source of truth; **Backups** now correctly targets the compose container (`v0.3.33` fix).
